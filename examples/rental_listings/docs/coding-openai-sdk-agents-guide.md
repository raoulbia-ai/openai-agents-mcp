# A Developer's Guide to Creating Agents with the OpenAI SDK

This guide provides a comprehensive overview of creating agents using the OpenAI SDK, drawing from various examples in the `examples` directory. We'll analyze different approaches, complexity levels, and best practices for building effective agents.

## Introduction to Agents

Agents are autonomous or semi-autonomous entities that can interact with users and systems to achieve specific goals. The OpenAI SDK provides a powerful framework for building agents that leverage the capabilities of OpenAI's language models.

## General Agent Creation Process

The typical process for creating an agent involves the following steps:

1.  **Define the agent's role and capabilities:** Determine the agent's purpose, the tasks it should perform, and the tools it will need.
2.  **Configure the agent:** Set up the agent's settings, including the model to use, system prompt, and any custom instructions.
3.  **Define tools (if applicable):** Create custom tools that the agent can use to interact with external systems or perform specific actions.
4.  **Implement the agent's logic:** Write the code that handles user input, interacts with the model, and executes tools.
5.  **Run the agent:** Deploy and run the agent, allowing it to interact with users and systems.

**Key Concepts:**

- **`name`:**  A human-readable name for the agent.

### Output Guardrails

This example demonstrates how to use output guardrails to validate and potentially intercept the agent's final output *before* it's returned to the user. This is useful for enforcing policies, checking for sensitive data, or ensuring output quality.

**File:** `examples/agent_patterns/output_guardrails.py`

**Key Concepts:**

-   **`@output_guardrail` decorator:** Marks a function as an output guardrail.
-   **`GuardrailFunctionOutput`:**  The return type for guardrail functions, similar to input guardrails.
-   **`OutputGuardrailTripwireTriggered` exception:** Raised when an output guardrail's tripwire is triggered.

**Code Snippet:**

```python
class MessageOutput(BaseModel):
    reasoning: str = Field(description="Thoughts on how to respond to the user's message")
    response: str = Field(description="The response to the user's message")
    user_name: str | None = Field(description="The name of the user who sent the message, if known")


@output_guardrail
async def sensitive_data_check(
    context: RunContextWrapper, agent: Agent, output: MessageOutput
) -> GuardrailFunctionOutput:
    phone_number_in_response = "650" in output.response
    phone_number_in_reasoning = "650" in output.reasoning

    return GuardrailFunctionOutput(
        output_info={
            "phone_number_in_response": phone_number_in_response,
            "phone_number_in_reasoning": phone_number_in_reasoning,
        },
        tripwire_triggered=phone_number_in_response or phone_number_in_reasoning,
    )


agent = Agent(
    name="Assistant",
    instructions="You are a helpful assistant.",
    output_type=MessageOutput,
    output_guardrails=[sensitive_data_check],
)

# ... (inside the main loop)

    result = await Runner.run(
        agent, "My phone number is 650-123-4567. Where do you think I live?"

    print(f"Guardrail tripped. Info: {e.guardrail_result.output.output_info}")
```

-   The `sensitive_data_check` function is decorated with `@output_guardrail`.

## Agent Lifecycle and Hooks

The OpenAI SDK provides mechanisms to monitor and interact with the agent's lifecycle through `AgentHooks`. This allows you to track events like agent start, end, handoffs, and tool usage.

**Example:** `examples/basic/agent_lifecycle_example.py`

**Key Concepts:**

- **`AgentHooks`:** A class that defines callback methods for various lifecycle events.
- **`on_start`:** Called when an agent starts.
- **`on_end`:** Called when an agent finishes.
- **`on_handoff`:** Called when an agent hands off to another agent.
- **`on_tool_start`:** Called when an agent starts using a tool.
- **`on_tool_end`:** Called when an agent finishes using a tool.
- **`hooks` parameter:** Used in Agent constructor to attach custom hooks.

**Code Snippet:**

```python

        self.display_name = display_name

        self.event_counter += 1
```

The `examples/email` directory contains an example of an agent that can send emails.  **Note:** This example is marked as "NOT TESTED!" in the code.

**File:** `examples/email/email-agent.py`

**Key Features:**

-   **`send_email` tool:**  Uses the `smtplib` library to send emails.
-   **Environment Variables:**  Uses environment variables (`GMAIL_USER`, `GMAIL_APP_PASSWORD`) to store sensitive credentials.
-   **Email Composition:** Uses the `email.mime` module to construct email messages.

```python
import smtplib
from email.mime.multipart import MIMEMultipart
from email.mime.text import MIMEText

@function_tool
def send_email(wrapper: RunContextWrapper[None]) -> str:
    """Send an email to a specified recipient."""
    recipient = wrapper.context.get("recipient")
    subject = wrapper.context.get("subject")
    body = wrapper.context.get("body")

    if not recipient or not subject or not body:
        return "Error: Missing recipient, subject, or body."

    msg = MIMEMultipart()
    msg['From'] = gmail_user
    msg['To'] = recipient
    msg['Subject'] = subject
    msg.attach(MIMEText(body, 'plain'))

    server = smtplib.SMTP('smtp.gmail.com', 587)
    server.starttls()
    server.login(gmail_user, gmail_app_password)
    text = msg.as_string()
    server.sendmail(gmail_user, recipient, text)
    server.quit()

    return f"Email sent to {recipient}."


email_agent = Agent(
    name="Email Sender",
    instructions="You are an agent that sends emails.",
    tools=[send_email],
)
```

**Explanation:**

-   **`instructions` as a callable:** Instead of a string, the `instructions` parameter of the `Agent` constructor can be a function.
-   **`RunContextWrapper`:** Provides access to the run context, including any custom context objects.

**Code Snippet:**

```python
class CustomContext:
    def __init__(self, style: Literal["haiku", "pirate", "robot"]):
        self.style = style


def custom_instructions(
    run_context: RunContextWrapper[CustomContext], agent: Agent[CustomContext]
) -> str:
    context = run_context.context
    if context.style == "haiku":
        return "Only respond in haikus."
    elif context.style == "pirate":
        return "Respond as a pirate."
    else:
        return "Respond as a robot and say 'beep boop' a lot."


agent = Agent(
    name="Chat agent",
    instructions=custom_instructions,  # Pass the function here
)

# ... (inside main)

```

**Explanation:**

-   A `CustomContext` class is defined to hold custom context data (in this case, a `style`).
-   The `custom_instructions` function takes a `RunContextWrapper` and the `Agent` as arguments and returns a string that will be used as the system prompt.
-   The `instructions` parameter of the `Agent` constructor is set to the `custom_instructions` function.
-   When `Runner.run` is called, the `custom_instructions` function is invoked, and its return value is used as the system prompt.
- The example shows how the system prompt changes based on the randomly selected `style`.

-   The `run_streamed` method is used to process the agent's response in a streaming fashion.
-   The `result.current_agent` attribute is used to track which agent is currently active after a handoff.
